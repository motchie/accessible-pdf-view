Prompted by #1, with thanks to its reporter: a PDF whose structure tags were ignored, and whose Japanese text read as noise.

## What changes for a reader

- **Structure tags are read even when the PDF does not declare itself Tagged PDF.** Some PDFs carry a complete structure tree but leave out the `/MarkInfo /Marked true` declaration the standard requires. Until now the Reader ignored such a tree and inferred the structure from the layout. It now reads the author's tags — headings, reading order, alternative text — provided they carry at least half of the text on the pages, since without the declaration nothing says the tree is the whole document.
- **The document information panel says when a PDF does not conform.** For such a PDF, "Structure tags" reads **Yes, but not declared as Tagged PDF**, and a note explains that ISO 32000 and PDF/UA require the declaration, so other viewers and assistive technology may not use the tags.
- **The panel no longer says a tagged PDF has no tags.** Switching a tagged PDF to the inferred reading used to show the note for untagged PDFs. That note now appears only for a PDF with no structure tree.
- **Japanese and Chinese text in fonts without a ToUnicode map is read.** In the inferred reading and the Markdown view, text set in CID fonts that rely on their character collection came out as noise and the page was flagged for OCR. (Korean already read correctly.) It now reads as it does in other PDF readers, characters outside the BMP included.

## Under the hood

- pdf-inspector is a patched build of 1.23.0 (`1.23.0-apv.2`) in `vendor/pdf-inspector-wasm/`, carrying the fix offered upstream as firecrawl/pdf-inspector#594. Its README records the source commit, build command and hash, and when it goes: once a pdf-inspector release on npm has the fix.
- pdf-inspector's licence, with the notice for the Adobe CMaps its binary embeds, now ships in the extension as `pdf-inspector/LICENSE`. Earlier builds shipped the binary without it.
- A release workflow builds, tests and submits the extension to the Chrome Web Store from a version tag.

## 日本語

#1 の報告をきっかけにした版です。構造タグが使われず、日本語が文字化けしていた PDF を報告してくださった方に感謝します。

- **Tagged PDF の宣言がない PDF でも、構造タグを読むようになりました。** 構造ツリーがあっても、規格が求める `/MarkInfo /Marked true` の宣言がない PDF があります。これまではそのツリーを使わず、レイアウトから構造を推測していました。今後は作成者のタグ（見出し、読み順、代替テキスト）を読みます。ただし、宣言がない以上、ツリーが文書全体だとは限らないため、ページの文字の半分以上をタグが含んでいる場合に限ります。
- **規格に沿っていないことを文書情報パネルに表示します。** そのような PDF では「構造タグ」が **あり（Tagged PDF の宣言なし）** となり、ISO 32000 と PDF/UA が求める宣言がないため、ほかのビューアや支援技術ではタグが使われないことがある、という注記が出ます。
- **タグ付きの PDF を「タグなし」と表示しなくなりました。** タグ付きの PDF を推測の読み取りに切り替えると、タグのない PDF 向けの注記が出ていました。この注記は、構造ツリーのない PDF でだけ出るようにしました。
- **ToUnicode のないフォントの日本語・中国語を読めるようになりました。** 推測の読み取りと Markdown 表示で、文字の対応を文字集合に頼る CID フォントの文字が文字化けし、ページが OCR 対象と判定されていました（韓国語はもともと読めていました）。今後は、ほかの PDF リーダーと同じように読めます。BMP 外の文字も含みます。
- 内部的には、pdf-inspector を 1.23.0 に修正を当てた版（`1.23.0-apv.2`）に差し替えています。修正は上流に firecrawl/pdf-inspector#594 として提案済みで、修正を含む版が npm に出たら正規版に戻します。pdf-inspector のライセンス文（埋め込まれた Adobe CMap の告知を含む）も、拡張機能に同梱するようになりました。
