Accessible PDF View is now on Firefox Add-ons as well as the Chrome Web Store, and this version fixes what reading it in Firefox showed: a Japanese interface announced as English, and settings that do nothing there. Radio buttons are now named by their label alone.

## What changes for a reader

### Firefox

- **Accessible PDF View is on Firefox Add-ons**, for Firefox 144 or later on desktop: https://addons.mozilla.org/firefox/addon/accessible-pdf-view/ . 0.2.4 was the first version listed there; from this one on, each version is submitted to both stores, and each store publishes it after its own review.
- **A Japanese interface is no longer announced as English.** With NVDA, 「英語」 came before the Reader's Japanese text, as in 「リンク 英語 本文へスキップ」. Firefox tells screen readers the language an element had when it was created, and the page started out English and was switched afterwards. Its language is now set before the page is built, and switching it in the settings recreates the interface in the new language. This was checked in Firefox on Windows by reading the language each element reports, before and after switching, and by listening with NVDA to the top of the Reader and the structure picker. (#40)
- **Settings that do nothing in Firefox are left out.** Firefox has no on-device model an extension can use, so the Reader cannot generate image descriptions or run OCR there. The 「AI が生成する文章の言語」 setting, and the note under 「構造の読み取り方」 about generated results, no longer appear in Firefox. In Chrome they appear as before, on any machine. (#32, #38)

### Every browser

- **Each radio button is named by its label alone.** In 「構造の読み取り方」 and in the settings, the explanation under each choice used to be part of the radio's name. The whole paragraph was spoken every time the radio was reached, and NVDA announced it as clickable. The explanation is now the radio's description, still shown on screen. With NVDA in Firefox it is read after the name when the radio has focus; how often a description is spoken varies between screen readers, and the settings panel's radios were not listened to. Clicking the explanation no longer selects the radio; clicking its name does. (#34)
- **Switching the interface language rebuilds the Reader's interface**, so that the new language reaches screen readers (see #40 above). OCR that is still running at that moment is stopped, and an image-description run may be; what either had already finished is kept. (#40)
- **The document's title keeps the document's language.** The page heading is the PDF's own title when it has one. It now carries the language the PDF declares, as the text below it does, so a Japanese title read with the interface in English is still marked Japanese. A title taken from the file name follows the interface, as before. (#42)
- **PDF.js 6.5.438** (was 6.4.299). A tagged PDF whose structure tree has no ParentTree now offers its tagged readings. Until now such a file could only be read by inference. This was measured on 16 documents, each opened with every reading preference: the structure the Reader exposes is the same as before, and every image decodes to the same pixels.

## Not changed yet

- **In Firefox, the Reader's static content is exposed as clickable** (#33). With TalkBack it is announced as something to double-tap. With NVDA on Windows, the paragraphs and headings were not announced as clickable; 「クリック可能」 was heard once, as focus entered the page, which is probably this cause.
- When the interface language is switched with a page open, the page's own name keeps the old language until the page is reopened. Everything inside the Reader follows the switch.

## Under the hood

- The release workflow submits each tagged version to Firefox Add-ons as well as the Chrome Web Store, from separate jobs with separate credentials. The notes for Mozilla's reviewers travel with every version.
- `ACCESSIBILITY.md` states what the project aims for, what has been checked with which assistive technology, and how to report a barrier, with a form for it.

## 日本語

Accessible PDF View を、Chrome ウェブストアに加えて Firefox アドオンでも公開しました。このバージョンでは、Firefox で使ってみてわかった問題を直しています。日本語の画面が英語として読み上げられること、Firefox では働かない設定が表示されることの 2 つです。ラジオボタンの名前も、短い名前だけにしました。

### Firefox

- **Firefox アドオンで公開しています。** デスクトップ版の Firefox 144 以降が必要です（https://addons.mozilla.org/firefox/addon/accessible-pdf-view/ ）。Firefox アドオンに最初に掲載したのは 0.2.4 で、このバージョンからは、両方のストアに同じバージョンを提出します。公開されるのは、それぞれのストアの審査が終わってからです。
- **日本語の画面が「英語」として読み上げられなくなりました。** NVDA では、Reader の日本語の文字の前に「英語」と付き、「リンク 英語 本文へスキップ」のように読み上げられていました。Firefox は、要素が作られたときの言語をスクリーンリーダーに伝えます。Reader のページは英語として作られ、そのあとで日本語に切り替えていたので、この問題が起きていました。今後は、ページを作る前に言語を決めます。設定で言語を切り替えたときは、画面をその言語で作り直します。Windows の Firefox で、各要素がどの言語として伝わっているかを、切り替えの前後で読み取って確かめました。NVDA では、Reader の上のほうと「構造の読み取り方」を聞いて確かめています。（#40）
- **Firefox では働かない設定を表示しなくなりました。** Firefox には拡張機能から使える端末内の AI モデルがないため、画像の説明も OCR も使えません。そこで Firefox では、「AI が生成する文章の言語」の設定と、「構造の読み取り方」の下にある生成結果についての注記を表示しなくなりました。Chrome では、どのパソコンでもこれまでどおり表示します。（#32、#38）

### すべてのブラウザー

- **ラジオボタンの名前を、短い名前だけにしました。** 「構造の読み取り方」と設定画面では、各選択肢の下にある説明文までがラジオボタンの名前に含まれていました。そのため、ラジオボタンに移るたびに説明文全体が読み上げられ、NVDA は説明文を「クリック可能」と伝えていました。今後は、説明文はラジオボタンの「説明」として伝わり、画面にもこれまでどおり表示します。Firefox と NVDA では、ラジオボタンにフォーカスすると、名前のあとに説明文が読まれます。説明をどこまで読むかは読み上げソフトによって違い、設定画面のラジオボタンは聞いて確かめていません。説明文をクリックしてもラジオボタンは選ばれなくなりました。名前をクリックすれば選べます。（#34）
- **表示言語を切り替えると、Reader の画面を作り直します。** 新しい言語をスクリーンリーダーに伝えるためです（上の #40 を参照）。その時点で実行中の OCR は止まり、画像の説明も止まることがあります。それまでに終わった分は残ります。（#40）
- **文書の題名に、文書自身の言語を付けるようにしました。** ページの見出しには、PDF に題名があればそれを使います。この見出しに、本文と同じく PDF が宣言している言語を付けるようにしました。表示言語を英語にしていても、日本語の題名は日本語として伝わります。ファイル名を題名にしている場合は、これまでどおり画面の言語に従います。（#42）
- **PDF.js 6.5.438**（これまでは 6.4.299）にしました。ParentTree のない構造タグ付き PDF でも、構造タグによる読み取りを選べるようになりました（これまでは推測による読み取りだけでした）。16 の文書をすべての読み取り方で開いて比べ、Reader が示す構造と、画像の中身が以前と同じであることを確かめています。

まだ変えていないこと：

- **Firefox では、Reader の静的な内容がクリック可能として伝わります**（#33）。TalkBack では「ダブルタップして有効」と読み上げられます。Windows の NVDA では、段落や見出しは「クリック可能」と読まれませんでした。ページにフォーカスが入ったときに一度だけ「クリック可能」と聞こえ、これはおそらくこの原因によるものです。
- ページを開いたまま表示言語を切り替えると、ページそのものの名前は、開き直すまで前の言語のままです。Reader の中の要素は、切り替えた言語に従います。
